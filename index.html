Le dashboard ne lit que ce document. Tout ce qu'il affiche en dérive : si un champ manque, la colonne correspondante disparaît. C'est la seule chose à figer avant d'écrire le script du NAS et la Lambda.

Un point de mesure — ce que le NAS envoie chaque minute

  "ts":    "2026-08-02T10:23:00Z",   // horodaté par le NAS, pas par la Lambda

  "sent":  5,
  "lost":  0,                        // 0..5

Réponse de la Lambda au GET du front 
GET /points?from=2026-08-01T10:00:00Z&to=2026-08-02T10:00:00Z

{
  "from": "...", "to": "...", "step": 60,
  "points": [ /* les objets ci-dessus, triés par ts croissant */ ],
  "gaps":   [ { "from": "...", "to": "...", "minutes": 7 } ]
}

Les trous sont calculés côté serveur et renvoyés explicitement, plutôt que déduits par le navigateur. Même règle pour tout le monde, et une alerte SNS pourra réutiliser le même calcul le jour où tu en voudras une.
